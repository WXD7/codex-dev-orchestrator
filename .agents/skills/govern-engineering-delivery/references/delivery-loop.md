# Delivery loop

1. Compile and freeze the work contract. If critical Acceptance, safety, recovery or observability information is missing, stop for clarification.
2. Route to the most compatible existing owner Topic. Start fresh only for genuinely independent work, explicit contamination, or adversarial falsification.
3. The owner investigates, implements and records changed behavior plus deterministic evidence.
4. Run repository-defined deterministic gates. Failures return to the owner as part of the one consolidated repair allowance.
5. Run the risk-selected, fresh-context, read-only verification lanes. Aggregate only evidence-backed findings.
6. If blocking findings exist and no repair has been used, send one deduplicated brief to the same owner Topic, then rerun all deterministic gates and affected/regression-sensitive lanes.
7. If a second failure, disagreement, missing evidence or contract drift remains, stop and escalate.
8. Publish user/operator evidence with LobeHub Acceptance. Each repair uses a new immutable round.
9. Ask for the accountable human decision at experience/aesthetic, irreversible/external-effect and final merge/release boundaries.

The loop stops when evidence supports human Acceptance, when the human rejects, or when policy requires escalation. It never loops indefinitely and never interprets silence as approval.
